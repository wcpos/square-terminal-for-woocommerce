# Square Terminal for WooCommerce 0.8.7

Closes an edge case left by 0.8.6 on stores that use WooCommerce's HPOS data caching with a persistent object cache.

## Fixed

- **A paid order could get a false "Refund may be required" note.** 0.8.6 reloads the order inside the per-order lock with WooCommerce's caches cleared. With HPOS data caching on, WooCommerce clears an order's cached meta only when its cached row was deleted successfully. If the row entry had already expired from a persistent object cache, the meta entry stayed. A webhook or background sweep that had waited on another request then read the paid order with its old meta. It treated the one real payment as a second capture and added a note asking the merchant to check for a refund. The order was not completed twice. The plugin now clears the order's meta cache itself.

## Upgrade

No configuration changes are required. Stores without HPOS data caching are not affected. On an affected store, a "captured an additional payment on an already-paid order" note can be checked against the Square Dashboard: if Square shows only one payment for the order, no refund is needed.
